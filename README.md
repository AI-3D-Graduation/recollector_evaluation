## 핵심 비교 지표

### 기하학적 복잡도 (Geometry Complexity)

#### 삼각형 수 (Triangle Count)
- **의미**: 3D 모델의 폴리곤 복잡도
- **영향**: 
  - ↑ 많을수록: 더 디테일하고 부드러운 표면
  - ↓ 적을수록: 렌더링 성능 향상, GPU 부담 감소
  - 모델 생성물 퀄리티의 가장 핵심
- **비교 기준**:
  - 비슷한 디테일에서 삼각형 수가 적은 쪽이 우수
  - 모바일: ~10만개 이하
  - PC/웹: ~100만개 이하
  - VR: ~5만개 이하 (양안 렌더링)

#### 정점 수 (Vertex Count)
- **의미**: 3D 공간상의 점(point) 개수
- **영향**: 
  - GPU 메모리 사용량
  - 버텍스 셰이더 처리 부하
- **비교 기준**:
  - 정점 당 더 많은 디테일을 표현하면 효율적

#### Vertices/Triangles 비율
- **의미**: 인덱싱 효율성 지표
- **최적 범위**: **0.5 ~ 1.5**
- **평가**:
  - 비율이 1.0에 가까우면 인덱스 버퍼를 효율적으로 사용
  - 3.0 이상이면 중복 정점이 많아 비효율적
  - 0.3 이하면 정점이 과도하게 공유되어 UV/Normal이 왜곡될 수 있음

#### 프리미티브 수 (Primitive Count)
- **의미**: 렌더링 단위 (각 Primitive = 1 Draw Call)
- **영향**: CPU 오버헤드
- **비교 기준**:
  - 적을수록 좋음 (배칭/머징 최적화)
  - 200개 이상이면 문제 가능성

### 텍스처 퀄리티

#### 텍스처 해상도
- **주요 크기**:
  - 512×512 (0.5K): 저품질, 모바일 최적화
  - 1024×1024 (1K): 일반 품질
  - 2048×2048 (2K): 고품질, 웹/모바일 권장
  - 4096×4096 (4K): 매우 고품질, PC 전용
  - 8192×8192 (8K): 초고품질, 고사양 PC 전용

- **메모리 계산**:
  - RGBA PNG (비압축): width × height × 4 bytes
  - 예: 2K 텍스처 = 2048 × 2048 × 4 = 16MB
  - 예: 4K 텍스처 = 4096 × 4096 × 4 = 64MB

- **비교 기준**:
  - 같은 시각적 품질이라면 작은 텍스처가 우수
  - 여러 작은 텍스처보다 하나의 큰 아틀라스가 효율적 (Draw Call 감소)

#### 텍스처 개수
- **영향**: 
  - 메모리 사용량
  - 텍스처 바인딩 오버헤드
- **비교 기준**:
  - 적을수록 좋음 (단, 중복 제거 및 아틀라싱 필요)

#### 총 텍스처 픽셀 (Total Texture Pixels)
- **의미**: 모든 텍스처의 픽셀 수 합계
- **계산**: Σ(width × height)
- **비교 기준**: 실제 메모리 사용량을 나타내는 좋은 지표

#### 텍스처 포맷
- **PNG**: 무손실, 투명도 지원, 파일 크기 큼
- **JPEG**: 손실 압축, 파일 크기 작음, 투명도 없음
- **WebP**: 효율적 압축, 브라우저 지원 필요
- **KTX2/Basis Universal**: GPU 압축, 최고 효율성

### 머티리얼 복잡도

#### PBR (Physically Based Rendering) 텍스처
- **Base Color**: 기본 색상 (필수)
- **Metallic/Roughness**: 금속성/거칠기 (PBR 핵심)
- **Normal Map**: 표면 디테일 증가 (추천)
- **Occlusion Map**: 주변광 차폐 (현실감↑)
- **Emissive Map**: 발광 효과 (선택)

#### 비교 기준
- **Normal Map 유무**: 
  - ✅ 있음: 적은 폴리곤으로도 디테일 표현 가능
  - ❌ 없음: 폴리곤으로만 디테일 표현
  
- **Occlusion Map 유무**:
  - ✅ 있음: 틈새/구석의 그림자가 현실적
  - ❌ 없음: 밋밋한 느낌

- **텍스처 수 vs 품질**:
  - 많은 텍스처 = 높은 품질 + 높은 메모리
  - 적절한 균형 필요

#### Metallic/Roughness 값
- **Metallic Factor**:
  - 0.0: 비금속 (나무, 플라스틱, 천)
  - 1.0: 금속 (철, 금, 은)
  
- **Roughness Factor**:
  - 0.0: 매끄러움 (거울, 광택)
  - 1.0: 거칠음 (돌, 천, 고무)

## 품질 평가 체크리스트

### ✅ 기본 품질 (필수)
- [ ] 정점/삼각형 비율이 0.5~1.5 범위
- [ ] 모든 메시에 NORMAL 속성 존재
- [ ] 텍스처가 있다면 TEXCOORD_0 존재
- [ ] 인덱스 버퍼 사용 중
- [ ] 파일 크기가 타겟 플랫폼 기준 이내

### ⭐ 고품질 (권장)
- [ ] Normal Map 사용으로 표면 디테일 증가
- [ ] Occlusion Map으로 현실감 향상
- [ ] PBR 머티리얼 제대로 설정 (Metallic/Roughness)
- [ ] 텍스처 해상도가 적절 (2K 권장)

## 시나리오 예시

### 시나리오 1: 서로 다른 2개 캐릭터 모델 비교
**모델 A**
- 삼각형: 50,000
- 텍스처: 2K × 5개 (Base, Normal, Metallic/Roughness, Occlusion, Emissive)
- 파일 크기: 8MB
- Normal Map: ✅

**모델 B**
- 삼각형: 150,000
- 텍스처: 4K × 3개 (Base, Normal, Metallic/Roughness)
- 파일 크기: 25MB
- Normal Map: ✅

**평가**:
- **디테일**: B가 더 높은 폴리곤 수로 우수
- **텍스처**: B가 더 높은 해상도 (4K vs 2K)
- **결론**: 타겟이 모바일/웹이면 A, 고사양 PC면 B

### 시나리오 2: 단일 모델 퀄리티 평가
**모델 A**
- 삼각형: 70,000
- 텍스처: 3K × 3개 (Base, Normal, Metallic/Roughness)
- 파일 크기: 12MB
- Normal Map: ✅

**평가**:
- **산업**: 애니메이션과 같은 비실시간/고품질 렌더링에는 부적합, 게임같은 실시간 렌더링에는 적합
